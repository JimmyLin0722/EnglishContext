# BUG-001 離線時按麥克風，分數區仍顯示前一次的評分

## 重現步驟

| 步 | 操作 |
| :--- | :--- |
| 1 | 以 Chrome 開啟 `dist/english-master-track.html`（自動化：`tests/e2e/e2e-speech.mjs` 的 TC-08-14b，注入假 `SpeechRecognition`） |
| 2 | 抽認卡頁任一張卡（例：Scalability），按麥克風並完成一次辨識，分數區顯示「辨識吻合度 100 綠燈」 |
| 3 | 不換卡，將裝置斷網（DevTools Network 設為 Offline；自動化以 CDP `Network.emulateNetworkConditions offline: true`，`navigator.onLine === false`） |
| 4 | 再按一次麥克風按鈕 |

## 預期結果（引用 AC）

AC-08-14：「按下麥克風按鈕 → 顯示「語音辨識需要網路連線」，按鈕回到待機狀態，**不顯示分數**，不拋出未處理錯誤」。

## 實際結果

- 訊息「語音辨識需要網路連線」正確出現，按鈕回到 `idle`，無未處理例外。
- 但分數區仍顯示上一次的結果，畫面同時出現離線訊息與分數：

```
FAIL TC-08-14b AC-08-14 先評分 100/綠燈，離線再按麥克風：訊息「語音辨識需要網路連線」、idle、
分數區仍顯示「辨識吻合度 100 綠燈 此分數比對的是語音辨識出的文字，不代表音素層級的發音準確度」
```

- `EMT.store.getState().runtime.speech.lastResult` 仍為 `{"recognizedText":"the","targetText":"the","score":100,"light":"green"}`。
- 對照：同一張卡第一次按下（沒有前次結果）時正常（TC-08-14 通過）；進入聆聽後的權限錯誤、`network`、`no-speech` 等路徑會先清除結果（TC-08-09、TC-08-10、TC-08-14 第二段通過）。只有按下時已判定離線、尚未開始聆聽的路徑沒有清除。

## 可能原因（選填）

`src/app/views/speech-panel.js` 的 `onMicClick` 在 `stt.isOnline()` 為 false 時只呼叫 `setMessage(null)` 與 `endWith({ text: TEXT.offline … })`，未呼叫 `act("setSttResult", null)`；清除結果的動作只在 `startListening` 內執行，而離線時不會進入 `startListening`。建議在離線分支一併清除 `lastResult`。
