# BUG-006：廣告環境成立時，載入中 `.app-header__inner` 因 `scrollbar-gutter` 左移 7.5px（只有第二階段會發生）

> **人類決定（JimmyLin，2026-11-05，對話中回覆「都依建議」）**：延後到第二階段；填入廣告單元 ID 前必須修正或由人類接受。AC-52-05 仍未通過；本單維持 `open`。

**第一階段不受影響**：正式建置 `AD_SLOT_ID` 為 `null`，`html[data-ad-env]` 不存在（TC-50-02、TC-56-10 實測），此位移不會發生。**填入廣告單元 ID 前必須處理或由人類接受。**

## 重現步驟

1. `node tests/tools/build-ad-test.mjs <暫存目錄>` 產生已設定單元 ID 的測試建置。
2. 以 `tests/e2e/e2e-ad.mjs` 的 V-AD (b)（本機 HTTPS 模擬正式網址），一般捲軸（關閉 Playwright 預設的 `--hide-scrollbars`），1920×1080。
3. 用 Layout Instability API 記錄載入期間的 layout shift，比對第一階段（`dist/site`）與 v1.2.0。

## 預期結果（引用 AC）

AC-52-05：「受影響元素只可為頁尾與版面底部」。

## 實際結果

| 尺寸與捲軸 | 版本 | `.app-header__inner` 位移 | 時間（載入後） | layout shift 值 |
| :--- | :--- | :--- | :--- | :--- |
| 1920×1080 一般捲軸 | 廣告環境 | dx −7.5、dy 0 | 約 230 ms（廣告框建立前約 15 ms） | 0.0358 |
| 1920×1080 一般捲軸 | 第一階段、v1.2.0 | 無 | — | — |
| 1366×768 一般捲軸 | 廣告環境 | dx −7.5、dy 0 | 約 240 ms | 0.0835 |
| 1366×768 一般捲軸 | 第一階段、v1.2.0 | dx −7.5、dy 0（首屏內容撐出捲軸，舊有行為） | 約 235 ms | 0.0835 |
| 1366×768、1920×1080 隱藏捲軸 | 廣告環境 | dx −7.5、dy 0 | 約 233 ms | 0.0817、0.0358 |
| 1366×768、1920×1080 隱藏捲軸 | 第一階段、v1.2.0 | 無 | — | — |

未違反的部分：今日任務卡、3 格數據、近 7 天、資料備份的座標差皆為 0（TC-52-03）；廣告框建立後只有頁尾移動（非頁尾元素 0 筆）；廣告撐高才出現捲軸時，學習區塊與 header 都不左右移動（TC-52-05c，`scrollbar-gutter` 達到設計目的）。

判定：位移與廣告回傳無關，但只在廣告環境出現，且 header 不是「頁尾與版面底部」，依字面違反 AC-52-05。原始資料見 `tests/results/diag/r9-header-shift.json`。本項不是替身造成：位移早於腳本載入。

## 可能原因（選填）

首個畫格（約 111 ms）`data-ad-env` 尚未設定、`scrollbar-gutter` 為 `auto`；`services.ad.start` 設定屬性後的下一個畫格（約 223 ms）保留 15px，置中內容左移 7.5px（`tests/e2e/diag-r9-offline.mjs` 的逐畫格紀錄）。可能的方向：讓此樣式在第一個畫格前就生效，或由 PM 修改 AC-52-05 明列可接受的載入期 header 位移。屬設計取捨，建議先由 SD 判定。
