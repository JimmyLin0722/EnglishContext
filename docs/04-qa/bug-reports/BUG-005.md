# BUG-005：寬度 ≤ 640px 以 Tab 取得焦點的控制項被固定底部導覽列遮住（舊有缺陷）

> **人類決定（JimmyLin，2026-11-05，對話中回覆「都依建議」）**：接受為已知舊有缺陷，1.3.0 先部署，下一版修正。AC-38-09 仍未通過；本單維持 `open`。

**舊有**：v1.2.0（`git show 25e3c3f:dist/english-master-track.html`）以同腳本實測同樣發生，**不是 1.3.0 造成**；1.3.0 未改善也未惡化（`#footer-sources` 在 1.2.0 可見 0%，1.3.0 因頁尾加高後不再被遮）。

## 重現步驟

1. 視窗 375×667（`tests/e2e/diag-r9-focus.mjs`，`mobile: true`）；localStorage 有近 7 天資料。
2. 開啟主控台，捲到頂，按 Tab 依序移動焦點。
3. 每次按 Tab 後量 `document.activeElement.getBoundingClientRect()` 與 `#app-nav` 上緣。
4. 另對難易度設定、單字卡、模擬測驗頁重複。

## 預期結果（引用 AC）

AC-38-09 (a)：「資料備份」展開收合等控制項以 Tab 取得焦點時，有可見的焦點框（外框 ≥ 2 CSS px）。焦點在導覽列後面就看不到焦點框。

## 實際結果

| 版本 | 畫面 | 控制項 | 視窗內未被導覽遮住的比例 |
| :--- | :--- | :--- | :--- |
| 1.3.0、v1.2.0 | 主控台（有近 7 天資料） | `.db-backup__toggle`「資料備份」（AC-38-09 列出的控制項） | **0%** |
| 1.3.0、v1.2.0 | 難易度設定 | 金色級列 | 13% |
| 1.3.0、v1.2.0 | 難易度設定 | 「新增單字」 | 49% |
| 1.3.0、v1.2.0 | 單字卡 | `.fc-flip`、`.fc-next` | 94% |
| 1.3.0、v1.2.0 | 模擬測驗 | 選項 C／選項 D（本輪新發現，FE-89 未列） | 57%／0% |

390×844 下較少發生；全部數字見 `tests/results/diag/r9-focus.json`、`tests/results/tmp/r9-focus.txt`。

判定：只有 `.db-backup__toggle` 屬 AC-38-09 列舉的控制項，AC-38-09 判失敗。其他控制項不在該條字面內，屬同類問題，一併記錄。AC-27-03 的「正在輸入的欄位不被遮住」已通過，不受影響（輸入欄未被遮）。

影響：只有在窄視窗使用實體鍵盤時發生；觸控與滑鼠不受影響，因此嚴重度為 minor。

## 可能原因（選填）

瀏覽器捲動焦點元素時不會避開 `position: fixed` 的底部導覽。`styles/75-site-pages.css` 只對三頁連結設了 `scroll-margin-bottom`；其他畫面沒有。可能的修法：在 ≤ 640px 對 `html` 設 `scroll-padding-bottom`（導覽列高度＋安全區），但樣式檔與任務歸屬由 SD 判定。
